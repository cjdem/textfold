# 研究阅读卡

- 状态：已实现（2026-10-18）。数据契约见 [阅读卡格式](../reading-card-format.md)，实现说明见
  [开发说明](../DEVELOPMENT.md)。
- 创建日期：2026-10-18。
- 适用产品：TextFold Windows 桌面端及共用的本地网页阅读器。
- 本文是功能需求；实现记录见 `docs/changes/2026-10-18-reading-card.md`。

## 1. 目标

帮助硕博士生在精读一篇论文后，留下结构清楚、可以编辑、能够回查原文的阅读记录，减少反复翻找方法、实验条件和结论的时间。

研究阅读卡围绕四个问题组织内容：

1. 研究问题与贡献：作者解决什么问题，提出了什么贡献？
2. 方法与适用前提：方法如何工作，依赖哪些假设和条件？
3. 数据与实验设置：使用什么数据、基线、指标和关键参数？
4. 结果与局限：得到什么结果，结论的成立范围和限制是什么？

成功标准：用户打开一篇已经阅读的论文，能从阅读卡快速找到以上信息，并从具体条目回到支撑它的原文。

## 2. 首版范围

首版提供单篇论文的阅读卡生成、查看、人工编辑、原文追溯、本地保存和 Markdown 导出。

- 每篇文档维护一张当前阅读卡，生成候选内容不直接覆盖当前卡。
- 支持已有论文来源及用户导入的论文 PDF；不能只根据来源类型判断一份文件是否是论文。
- 非论文材料也允许手工填写；自动生成时，不适用的栏目明确标记，不强行套入实验论文结构。
- 支持简体中文和英文，首次生成默认使用当前阅读语言。已保存卡片保持自己的语言，切换阅读语言不自动翻译、重新生成或覆盖卡片。
- 自动生成由用户主动触发，打开论文、切换层级、切换语言均不自动调用模型。
- 没有可用模型时，仍能新建、编辑和保存手工阅读卡；自动生成入口说明需要配置模型。

本期不包含课题空间、跨论文对照、跨文档问答、完整实验复现工具、Zotero 写回或自动撰写文献综述。

## 3. 卡片内容

### 3.1 基本信息

显示文档标题、作者、年份或日期、来源链接，以及已有的 DOI、版本和 citekey。只展示实际存在的信息，不让模型猜测缺失的书目信息。

同时记录卡片语言、创建和更新时间。使用模型生成时，保存生成时间、模型标识和对应的原文版本或内容指纹，便于判断卡片是否过期。

本期不扩展为完整的书目编辑或引用格式管理功能。

### 3.2 四个内容栏目

| 栏目 | 应记录的内容 | 边界 |
|---|---|---|
| 研究问题与贡献 | 研究对象、待解决的问题、作者声称的主要贡献，以及文中对既有工作的区别描述 | 区分作者声称的贡献与已经通过实验或论证支持的结果，不自行断言“首次”或“领先” |
| 方法与适用前提 | 核心方法或流程、输入输出、关键机制、假设、适用条件 | 保留关键限定条件；论文未写明的方法细节不自行补全 |
| 数据与实验设置 | 数据集或样本、划分方式、预处理、对比基线、评价指标、关键参数、资源和实验协议 | 按实验或数据集组织，避免把不同实验的设置混在一起；理论论文允许标为“不适用” |
| 结果与局限 | 主要定量或定性结果、对应实验条件、作者明确讨论的局限和有效范围 | 数字保留单位、指标方向、对照对象和成立条件；不把相关性改写成因果关系 |

每个栏目由可单独编辑的条目组成，允许增加、修改、删除和调整顺序。生成内容以简洁要点为主，不以凑满篇幅为目标。

对于缺失或不适用的信息：

- 原文没有找到相关说明时，显示“未找到明确说明”，不声称全文一定未报告。
- 明确不适用于该文档时，显示“不适用”及简短原因。
- 两处内容相互矛盾或不足以确定时，显示“待核查”，保留相关原文入口。
- 数值、单位、公式或表格内容提取不可靠时，提示回查原文，不自动修补为确定事实。

## 4. 证据与内容来源

### 4.1 逐条追溯

自动生成的事实条目必须关联一个或多个支撑段落、图注或可定位的表格。栏目标题和缺失信息提示不要求伪造引用。

每个证据至少保存：

- 文档 ID。
- 对应单元 ID 及章节信息。
- 一段简短原文摘录，用于用户核对和定位失效后的查找。
- 已有可靠映射时保存句子位置或 PDF 页码；没有映射时不编造页码。

点击证据后，阅读器跳转并展开对应原文；已有 PDF 对照能力能够定位时，同步使用。卡片引用必须能在当前缩放层级隐藏原文的情况下展开目标。

数据和结果来自表格时，证据应能指向表格及相关实验说明；不能只引用不包含结果数字的图表标题来证明数字。

没有有效证据的模型条目不能作为已核查事实展示，应标为“待核查”。引用存在只说明能够定位，不代表已经证明该条目准确。

### 4.2 区分模型与用户内容

- 标明条目是模型生成、用户编写，还是由用户修改过的生成内容。
- 模型生成内容默认是待用户核对的草稿，不因生成成功就显示为已确认。
- 用户可以标记某条“已核查”或恢复为“待核查”；修改条目正文或证据后重新进入待核查状态。
- 用户可在阅读器选中原文后，将其作为证据加入卡片的某个条目。
- 手工条目允许暂时没有引用，并清楚显示“未关联原文”；不强制用户为个人阅读记录提供引用。
- 本期自动生成专注于提取和概括文中内容，不主动生成原文未提出的学术批评或推测。

## 5. 用户流程与界面

### 5.1 首次使用

1. 用户在已打开的文档中进入“研究阅读卡”。
2. 尚无卡片时，提供“生成阅读卡”和“手工填写”入口。
3. 生成前可选择中文或英文，默认当前阅读语言。
4. 生成中显示进行状态，允许取消；生成失败给出可理解的原因并允许重试。
5. 生成完成后展示四个栏目及逐条证据，用户可以核对、编辑和保存。

卡片使用独立面板或视图呈现，能够方便地返回原文。入口与现有阅读工具保持一致，不把整张卡插入论文正文或缩放动画中。

### 5.2 编辑与保存

- 普通编辑自动保存到本地，显示“保存中”“已保存”或“保存失败”。
- 保存失败时保留尚未保存的编辑并允许重试，不把失败伪装为成功。
- 关闭后重新打开、刷新页面或重启应用，应恢复最近一次成功保存的卡片。
- 卡片独立于现有高亮、笔记、问答和生成层保存；编辑卡片不改变这些内容。
- 卡片属于文档的用户数据；文档移入回收目录时随文档保留，恢复文档后卡片仍可读取。

### 5.3 重新生成与文档变化

- 重新生成产生候选草稿，原有卡片和人工修改继续保留。
- 用户可以选择将候选条目加入或替换当前条目，也可以丢弃候选；未经选择不覆盖已有正文和证据。
- 生成失败、取消或返回结果不完整时，保留原卡片；部分候选须明确显示未完成。
- 原文版本或内容变化后，标记“原文已变化，需复核”，保留旧条目和摘录。
- 仅重新生成摘要层或译文，不应无故让基于未变原文的证据失效。
- 引用目标不存在时，提示定位失效并展示已保存摘录，允许重新关联，不能静默隐藏条目或跳到错误段落。

## 6. 生成规则

- 生成依据是当前文档的原始内容，已有分层摘要可帮助导航，不能作为唯一事实依据。
- 不使用联网搜索或其他论文补全当前论文没有交代的事实。
- 检查方法、实验、结果、讨论及附录等相关内容，不只根据摘要生成整张卡。
- 长文档分段处理时保留章节和证据对应关系；不能将只处理过部分内容的结果显示成完整阅读卡。
- 单段选文问答现有的篇幅限制不适用于整张阅读卡；实现时应使用适合结构化提取的独立生成流程。
- 模型输出需要进行结构、引用目标和必填信息校验；无效引用必须显示为待核查，或拒绝该条目并说明原因。
- 取消、重试和重复点击不得导致旧请求覆盖较新的人工修改，也不得产生多张相互冲突的当前卡片。

## 7. Markdown 导出

首版支持将当前已保存的阅读卡导出为一个 Markdown 文件，便于存入 Obsidian 或用于组会准备。

导出内容包括基本信息、卡片语言和更新时间、四个栏目、条目来源和核查状态、证据摘录及回到 TextFold 对应位置的链接。模型生成内容附生成来源说明；原文已变化或引用失效的提示也应保留。

导出使用用户当前编辑后的内容，不重新调用模型。没有填写的栏目保留缺失或不适用的说明。导出失败不影响卡片本地数据。

整篇 HTML 内嵌阅读卡、专用打印排版和批量导出不属于首版要求。

## 8. 实现约束与现有能力

实施前阅读 [开发说明](../DEVELOPMENT.md) 和 [贡献规则](../../CONTRIBUTING.md)。以下是可复用能力和需要注意的边界，不强制具体文件划分或 API 命名：

- [ladder.py](../../textfold/ladder.py) 已有方法、实验设置、结果、局限等段落角色，但角色与摘要不能替代原文核对。
- [notes.py](../../textfold/notes.py) 和 [笔记格式](../notes-format.md) 已有本地保存、段落引用、原文摘录等能力；阅读卡需要自己的数据契约，避免改变现有笔记格式的含义。
- [reader.js](../../textfold/web/reader.js) 已有段落展开、证据跳转和 Markdown 导出交互，可按需要复用。
- [store.py](../../textfold/store.py) 负责文档位置和生成层；卡片应跟随实际数据目录，而非写死仓库路径。
- 使用现有模型接入与配置方式，不要求用户为了阅读卡再配置一套服务。
- 论文与卡片内容保存在用户数据目录，不进入提交；密钥不进入卡片、日志或导出。
- 新增数据写入遵循项目的 UTF-8 和 ASCII 转义 JSON 约定，兼容中文 Windows 环境。
- 不修改解析器来迁就卡片，避免无必要地改变原文单元和公式、引用的编号。
- 阅读卡的生成、编辑和证据显示不能拖慢正文缩放；遵守项目的平滑度要求。若无法运行 `tools/zoombench.py` 的完整测量，交付时明确写“缩放平滑度未测量”。

## 9. 验收标准

1. **普通实验论文**：生成四个栏目，贡献、方法、实验设置、主要结果均可回查支撑原文；关键数字保留指标、单位和实验条件。
2. **理论或非实验论文**：不会编造数据集和基线；实验栏目可以明确标为不适用。
3. **缺少信息**：论文没有明确交代的参数显示为未找到说明或待核查，不用常识补齐。
4. **证据回查**：在 Topic 等折叠层级点击证据仍能展开正确原文；PDF 页码仅在有可靠映射时显示。
5. **人工编辑**：新增、修改、删除和调整条目后，刷新及重启仍保留已保存结果；现有高亮、问答和笔记不变。
6. **核查状态**：模型条目默认待核查；用户确认后可标为已核查；正文或证据修改后恢复待核查。
7. **重复生成**：已有人工编辑时重新生成，原卡片不被自动覆盖；可采用候选条目或丢弃候选。
8. **异常恢复**：模型不可用、请求失败、取消、部分生成、保存失败均有清晰状态，不丢失已有卡片和当前编辑。
9. **原文变化**：卡片显示需复核；失效引用保留摘录和重新关联入口，不隐藏已有记录。
10. **语言与导出**：中文、英文可分别作为卡片生成语言；切换阅读语言不改写已有卡片；Markdown 包含最终编辑内容、证据和状态，导出不触发模型调用。
11. **兼容性**：无卡片的旧文档照常打开；手工卡片在无模型时可用；应用和本地网页使用同一份卡片数据。

实施完成后运行项目要求的测试，并针对持久化、证据校验、候选内容采用和异常恢复补充必要测试；在真实阅读器中检查入口、编辑、原文跳转及导出。测试数据使用合成或可公开分发的材料，不依赖用户私人论文和外部模型服务。
