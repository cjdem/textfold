# `TEXTFOLD_NO_MODELS` asks no model, whatever model is named

**Date:** 2026-10-22
**Branch:** `worktree-no-models-guard`

## What and why

`TEXTFOLD_NO_MODELS=1` is the promise a test server, a CI run and a program that only stores documents rely on: no
model is called. It was enforced by `models.provider_list`, which lists no provider under the flag, so a model
*resolved by name* found nothing. A **spec** — the dict `resolve` returns, which a test or a direct caller may hold —
went straight to `_once` and was asked. (Upstream's commit names the command line's older default and an agent
runtime; neither exists in this fork: the command line and the server resolve first, and agent runtimes were removed.
The reachable bypass here is a spec handed directly to `llm.call`.) This change puts the check where every call
passes: `llm.call` refuses to ask a model while the flag is set. A reply already kept on disk is still read when the
caller passes a spec; a call naming a model id is refused at resolution before the cache is consulted, and a `force`
call is refused, because it would ask.

## The change

- `textfold/llm.py` — `os` is imported; after the cache read and before `_once`, a set `TEXTFOLD_NO_MODELS` raises
  `RuntimeError("No model is available: TEXTFOLD_NO_MODELS is set")`. The message starts with the server's
  "No model is available", so a job reports `no-model` as it does when no provider is configured.
- `docs/DEVELOPMENT.md` — the flag's paragraph now says it refuses every model, that a kept reply is still read, and
  that a forced call is refused.
- `tests/test_no_models.py` — new: a spec named as an API provider's and one named as Claude Code's are both refused
  with no call made; a reply kept under the flag is read; a forced call under it is refused; `_once` is mocked, so
  nothing can reach a model.
- `tests/test_agent_encoding.py`, `tests/test_reply_shapes.py` — the cache tests call a stand-in model, so they clear
  the flag for their own scope (the suite runs with it set), as upstream's `test_replace.py` change does.

## Decisions

- **The check is in `llm.call`, not in every caller.** Every model call in the app goes through it (`ladder`,
  `translate`, `links`, `notes`, `cards`, the questions about a paper); a check in each caller would be one more place
  to forget, and a spec can be handed to any of them.
- **Cache first, then refuse.** Upstream's order, and the flag's documented purpose: a caller holding a spec still
  reads a kept reply; only asking is forbidden. A `force` call skips the cache and is therefore refused, which is what
  "regenerate" means. A call naming a model id never reaches this check: `spec_of` resolves it first (and under the
  flag no provider is listed), so it fails there with "Model … is not available" and no model is called either way.
- **A model resolved by name already fails under the flag.** `models.provider_list` lists no provider, so `resolve`
  raises "Model … is not available" before `llm.call`; the new check is the backstop for a spec, not a replacement.
  Its message is left as it is: naming a model that no listed provider offers is what the user did, and the flag's
  message would be less precise there. No model is called either way.
- **The flag is read per call.** It is cheap, and tests and subprocesses set it in their own environment; caching it
  would make it unsettable after import.

## Concurrency and locks

None added. The flag is read from the process environment; `llm.call` asks no model before the check and writes
nothing there except creating the cache folder (`mkdir`, as it did before), and no lock is involved.

## How it was verified

- `python .claude/hooks/verify.py` — 259 tests, OK (baseline 257; 2 added).
- The new test refuses two named specs with `_once` mocked (so a call would be detected) and reads a kept reply.
- The suite itself runs with `TEXTFOLD_NO_MODELS=1`; before this change it passed with the stand-in model tests, and
  now it passes because those tests clear the flag in their own scope.
- `textfold-verifier` — no functional finding; it confirmed that every product model path goes through `llm.call`, that
  the guard is before the reasoning-level retry, and that the new test fails on the base commit. It corrected the
  record's inherited examples (the command line's default and an agent runtime do not exist here; the reachable
  bypass is a directly held spec), scoped "a kept reply is still read" to the spec form (a model id is refused at
  resolution before the cache), noted that the cache folder is created before the check (the record no longer says
  "writes nothing"), and corrected the second test spec's description.

## Pitfalls

- A non-ASCII reply cache from before R2 is a miss under `_read_cache`; under the flag that now raises "No model is
  available" instead of asking again. That is correct for a test server (asking is forbidden) but means such a cache
  is not refreshed while the flag is set.
- The flag does not stop a call that never reaches `llm.call`: the protocol modules (`llm_openai`, the Anthropic
  client) are internal, and no product code calls them directly; a future direct caller would bypass this check.
- A caller that catches `RuntimeError` broadly may swallow the refusal; the server's `_end` maps it to `no-model`,
  and the command line reports it.

## Rejected

- **Clearing the flag inside `llm.call` for cache reads.** The check only runs after a cache miss, so a cache read
  needs nothing special; forcing a call is exactly what must stay forbidden.
- **Checking the flag in `models.resolve` for a named model.** It already lists no provider under the flag, so a
  named id fails there without a call; changing its message would not stop any call the new check does not.
- **A settings value instead of the environment variable.** The flag is set per process (a test server, CI), not per
  reader; a settings file would be the wrong lifetime.
