# The smoothness ruler runs on Windows' GPU backend, and stops claiming it needs a Mac

**Date:** 2026-10-16
**Branch:** `worktree-zoombench-d3d11`

## What and why

`tools/zoombench.py` is the only way this project checks its first rule, "No
change may make the zoom less smooth". It launched Chromium with
`--use-angle=metal`, a macOS GPU backend, so on this Windows-only fork it was a
ruler that could not be held. This changes that one flag to Windows' Direct3D 11
backend and rewrites the five documents that still described the tool as needing
a Mac, so that the next person does not conclude the capability was lost with
the Mac.

This is step 1 of turning the fork Windows-only, done first because every later
change that touches the reader is measured against this ruler.

## The change

- `tools/zoombench.py` — `--use-angle=metal` → `--use-angle=d3d11` (the only
  runtime line); docstring now says Direct3D 11 and records that the Metal
  numbers measured before are a different, incomparable set; usage line's
  `python3` → `python`.
- `CLAUDE.md` — the "This fork" bullet no longer calls the metal flag a Mac-ism
  and no longer points at "line 40"; the "Optimizing" bullet no longer says the
  tool needs a Mac, only that it needs playwright and exported pages.
- `.claude/skills/optimize/SKILL.md` — the phase-2 warning no longer tells the
  user the tool needs a Mac's GPU.
- `.claude/skills/optimize/references/invariants.md` — same, plus the note that
  d3d11 numbers are not comparable with the Metal ones.
- `.claude/agents/textfold-verifier.md` — the verifier's own invariant line, same
  correction.
- `docs/changes/README.md` — the "Not measured" bullet said the smoothness rule
  "cannot be measured off a Mac"; it now says what is actually missing here
  (playwright and an exported page).

Nothing else in the repository was touched: no reader, renderer, parser or test
file, and no `plugins/`.

## How it was verified

- `python .claude/hooks/verify.py` — 85 tests, OK (6.2 s), before and after.
- `python -m py_compile tools/zoombench.py` — compiles.
- `git diff --check` — clean.
- `textfold-verifier` on the diff: no defect; three untidiness notes, all
  answered below under Rejected/Notes. It confirmed the only runtime line is the
  one flag, that no file under `plugins/` is in the diff, and that the three
  remaining "Metal" mentions (`tools/zoombench.py:11`, `CLAUDE.md:26`,
  `invariants.md:64`) are deliberate historical caveats, not claims that a Mac
  is needed.
- Repo-wide grep for `metal|Metal|needs a Mac|Mac's GPU|off a Mac` — no
  remaining assertion that the ruler needs a Mac.

## Not measured

- **Smoothness: unmeasured. The ruler was not run.** `playwright` is not
  installed on this machine (`ModuleNotFoundError: No module named 'playwright'`,
  checked with the main checkout's `.venv` Python) and there are no exported
  pages under `out/compare/`. So even the launch test could not be done. This
  change does not touch the reader, but the tool's own output also could not be
  produced, and that is a gap, not a pass.
- **That Chromium accepts `d3d11`.** Not confirmed by running anything. It is
  the documented ANGLE backend for Windows and Chromium's default there; no
  Chromium exists here to try it on.
- **That d3d11 numbers differ from the recorded Metal numbers.** Asserted on the
  reasoning that different GPU backends give a different frame-timing set; no
  frame traces from either backend exist to compare.

## Rejected / notes

- **Making the flag `os.name`-conditional** (d3d11 on Windows, metal elsewhere):
  rejected — this fork is Windows-only, and a branch that keeps the Mac backend
  alive is the code the conversion exists to remove.
- **Deleting `tools/zoombench.py` as "Mac code"**: rejected before this change was
  written. It is the only capability that can check the project's first rule on
  any machine; the flag, not the tool, was the Mac part. (Verifier note 1: the
  precise claim is that no capability is lost **on Windows** — the tool no longer
  produces Mac numbers, which is the intent.)
- **`python3` → `python` on `tools/zoombench.py:3`**: this one line is strictly
  item 6's kind of edit, kept here because item 1 rewrote this docstring and the
  fork cannot run `python3`. Until item 6 lands, `docs/DEVELOPMENT.md:325`,
  `CONTRIBUTING.md` and `README.md` still spell it `python3` (verifier note 3);
  `invariants.md:66` and this file already say `python`, so item 6 closes the
  gap.
